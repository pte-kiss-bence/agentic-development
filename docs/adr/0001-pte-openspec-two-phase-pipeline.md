# pte-openspec: planning chain and build stage are write-decoupled

The `pte-openspec-*` pipeline has two phases. The **planning chain** (`pte-openspec-to-epics` → `pte-openspec-to-stories` → `pte-openspec-bdd-tests`) produces a groomed, human-facing backlog: epics, story cards, and the declarative Gherkin embedded in each card, all lined up on the same `EPIC-…`/`STORY-…` trace IDs. The **build stage** (`pte-openspec-tdd-execute`) implements the change test-first from the OpenSpec **change tasks** via a red-green TDD loop.

The phases are **write-decoupled**: neither writes the other's artifacts. The build stage never edits epics, story cards, or their Gherkin; the planning chain never touches code or the change's tasks. But the build stage **reads the planning artifacts as read-only, best-effort context**: per task it locates the tracing story card (via the requirement-anchored `STORY-…` grammar and the epic's *Source Spec Reference* map) and its parent epic, takes the story's `## BDD Test` Gherkin as the acceptance criteria for that behaviour, and honours the epic's `## Cross-cutting Concerns` as constraints. This context is optional by design — the planning chain may have been skipped entirely (right-sizing, [ADR 0003](0003-right-size-the-planning-chain-per-change.md)), so a missing card never blocks the build: it falls back to task + spec.

The **OpenSpec spec** (`### Requirement` / `#### Scenario`) stays the single source of *behaviour*: both phases trace back to it, and when a planning artifact contradicts the task or spec, the build stage surfaces the conflict instead of silently picking a side. The cost of write-decoupling is that a story card and the code satisfying the same requirement can drift; the spec being the sole behavioural anchor is what keeps them reconcilable.

History: the original version of this ADR declared the phases fully decoupled ("the build stage does not read the epics/stories/Gherkin and does not key on the trace IDs"). Amended in place when `pte-openspec-tdd-execute` gained the read-only trace context (story BDD as acceptance criteria, epic constraints); write-decoupling and spec-as-sole-behaviour-source are unchanged. Earlier still, `README.md` described a single linear chain ("stage 4 consumes stage 3") — also wrong; the two-phase model stands.
